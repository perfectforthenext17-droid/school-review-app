**除了数据库，还需要注意的几个关键隐患**

* **API Key 泄露风险**：你当前代码中直接明文写了智谱 AI 的 API 密钥（如 `client = ZhipuAI(api_key="...")`）。一旦直接推送到 GitHub（尤其是公开仓库），代码扫描机器人几秒钟内就会抓取并封禁你的 Key。**必须**通过 Streamlit 官方提供的 Secrets 管理（在后台设置环境变量）或 `.gitignore` 隐藏配置文件来隔离 Key。


* **文件写入与并发限制**：多人同时在截止前扎堆上传时，单个进程处理多份图文解析加 AI 请求，可能会导致内存短暂暴增。需确保提取图片及合并图像后及时释放内存（不要常驻在内存变量中）。


* **未提交/待审状态的防重复上传**：需要确保在“待审”状态下前端限制继续提交，否则管理员后台正在看图片时，学生端再次覆盖上传会导致数据错乱。



---

**1~5MB 的文件大小，推送与托管够用吗？**

* **代码与 Git 层面完全够用**：你推送到 GitHub 的只是 **Python 源代码和依赖清单**，代码本身只有几十 KB，根本不需要把测试用的大文件推上去。


* **用户上传层面完全够用**：Streamlit 默认的文件上传上限是 **200MB**，每份 1~5MB 的 Word 文档在上传带宽和解压处理上都非常轻量，完全在承载范围内。
* **唯一需要注意的是存储上限**：如果是长期存放，100 份 5MB 文件就是 500MB。因此定期导出压缩包并清理历史大文件（或者只存云端对象存储桶，只在本地存审核状态）是更稳妥的做法。



---

**上传到 GitHub，对后续修 Bug 和更新方便吗？**

**非常方便，而且这是目前最标准、最高效的工作流**：

* **自动热更新**：只要你的 Streamlit Cloud 绑定了 GitHub 仓库，后续你在本地电脑上修改好代码，执行一次 `git push` 推送，云端网页会在几十秒内**全自动重新部署并生效**，不需要你重新手动配置任何服务器。


* **版本回退安全**：如果不小心改出了新 Bug，你可以随时在 Git 历史中一键回滚到前一个正常工作的版本，不会导致整个系统瘫痪。

---

**不使用梯子（不用代理），团队能正常使用吗？**

结论是：**使用网页的学生团队完全不受影响，但作为管理员的你有两个小环节需要留意**。

* **学生端（使用者）无需任何代理**：
* 团队成员打开的是 Streamlit Cloud 分配给你的线上网址（以 `streamlit.app` 结尾）。国内绝大多数家庭宽带和手机流量**可以直连访问该域名**，无需开启任何代理软件。


* 你的 AI 视觉审查调用的是**智谱 AI**（国内大模型），网络在国内完全直连，不会再出现之前 Google Gemini 的阻断问题。




* **你（维护者）需要注意的环节**：
* **推送代码到 GitHub 时**：GitHub 官网及 `git push` 操作在国内部分网络环境下偶尔会出现握手慢或超时。通常直连可用，但如果遇到网络拥堵，可能需要稍等片刻重试，或配置 GitHub 镜像加速。


* **云数据库节点**：如果未来切换远程数据库（如 Supabase），必须选择新加坡（Singapore）或日本东京节点，确保国内直连顺畅。
